# 课程内固定组队与项目选择

## 当前规则

- 学生先私下确定3—5人及组长，组长在课程中创建团队。
- 组长通过姓名或账号邀请本课程的学生；对方接受后才正式入队。
- 同一课程每名学生只能加入一个课程团队，有待处理邀请时须先处理邀请。不同课程独立。
- 人数达到3—5人、待确认邀请处理完成后，组长一次选满课程要求的不同项目并确认。默认2个；教师可在任何团队选题前调整完成数量。
- 同一课程团队用于所有选定项目，选定后成员及项目固定。各项目独立保存迭代、任务、正式成果、评审与成绩。
- 不同团队可以选择相同项目。
- 当前只允许选择未过最终截止、状态为已发布/进行中且评分维度合计100的项目。

## 从哪里开始

刷新浏览器 → 我的课程 → 软件工程 → 组队与选题。
也可点击侧栏“组队与选题”。课程项目页为“课程项目池”，展示可供选择的项目及统一的组队入口。

## 单队完整操作示例

1. 教师 teacher01：在课程项目池准备两个已发布、尚未截止、评分标准完整的项目，例如“校园失物招领系统设计”和“实验室预约系统”。在“组队与选题”检查每队需完成2个项目。
2. 组长 student01：打开“组队与选题”，点击“我是组长，创建课程团队”，名称填写“基因重组队”。
3. 组长：点击邀请组员，按姓名或账号选择 student03 未宁夏、student05 陈爽、student06 汪欣芸，发送邀请。
4. 三位组员分别登录自己的账号，打开同一课程的“组队与选题”，接受邀请。也可从站内通知打开邀请页面。
5. 组长刷新页面：核对4名已确认成员，没有待处理邀请。
6. 组长勾选两个项目，点击“确认选择（2 / 2）”，检查确认框中的团队、人数和项目数量后确认。
7. 团队页面出现两个项目入口。点击各项目的“进入项目工作台”，进入迭代与成果操作；两个项目均使用同一份4人名单。
8. 教师在课程团队列表检查团队、组长、已确认人数及所选项目。

## 异常检查

| 场景 | 预期 |
|---|---|
| 组员未接受邀请 | 不计入正式人数，不自动获得成员权限 |
| 尚不足3人 | 不允许确认选题 |
| 有未处理邀请 | 先接受/谢绝邀请，或由组长撤销，再选题 |
| 同课程再次建队或接受另一个邀请 | 被阻止 |
| 邀请人数加有效成员超过5人 | 被阻止 |
| 普通组员代替组长选题 | 被阻止 |
| 选择不足规定数量、重复项目、其他课程项目、已截止项目或未发布项目 | 被阻止，整次选题失败时不保留部分报名 |
| 选题后重新邀请或在项目里修改成员 | 被阻止，固定名单保持一致 |
| 切换两个已选项目 | 项目任务和成果独立，团队成员一致 |

## 历史数据与后续范围

原项目内的团队、任务、成果和成绩仍在原项目中保留。新流程从课程团队页面创建并接受邀请开始，历史项目团队不自动计入新选题进度。选题时若历史同名团队与当前课程团队的负责人及完整成员名单完全一致，可沿用其项目工作记录；不一致时会提示核实，避免覆盖历史归属。
