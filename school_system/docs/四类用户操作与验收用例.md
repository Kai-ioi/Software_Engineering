# 四类用户操作与验收用例

## 1. 体验方式与共同数据

从“我的课程 → 软件工程 → 课程项目 → 项目详情”进入项目工作台。先确认页面上的项目名称和操作团队，再选择办理入口。课程身份独立；团队负责人是该项目内的成员身份，不是另一种登录账号。

完整操作使用一个新项目“校园失物招领系统设计·联合验收”，避免修改已有样例成果和成绩。教师创建后，四名学生、助教及教师在同一套运行中的系统里操作。各自在自己电脑启动的 127.0.0.1 使用各自本地数据，GitHub 同步源代码；多人共同走查时由同一台电脑切换账号，或连接已经配置好的共同服务。

### 项目配置

- 项目要求：设计失物登记、线索查询、认领核验及归还流程。公开页面隐藏认领暗号、唯一特征及私人联系方式，包含证据不符、重复归还等异常处理。
- 团队人数：2—4 人；成绩权重：教师 70%，同伴互评 30%。
- 评分维度：需求与业务规则 40 分、流程与异常处理 35 分、验收与可追溯性 25 分。
- 项目截止：创建时设置为当前时间后至少 2 小时；组队开放时间早于当前时间，组队截止早于项目最终截止。
- 两队各建“第1轮·需求与流程”，迭代顺序均为 1。顺序是本团队内部的展示次序，两个团队各自维护。

## 2. 连贯体验路线

| 次序 | 切换到谁 | 入口与操作 | 检查结果 |
|---|---|---|---|
| 1 | 教师 | 软件工程 → 课程项目 → 新建项目，填写上述配置；保存草稿、发布、开始项目，设置组队窗口 | 草稿与已发布状态明确，学生能看到已发布要求 |
| 2 | 两位负责人 | 各自进入新项目 → 团队与成员 → 创建“拾光队”“寻迹队” | 团队属于新项目，负责人对应当前账号 |
| 3 | 两位普通组员 | 进入项目 → 团队与成员，分别申请拾光队、寻迹队 | 页面显示申请待审批；此时尚未获得有效成员权限 |
| 4 | 两位负责人 | 打开本团队详情，通过对应申请 | 各队恰好两名有效成员，两个账号看到同一成员关系 |
| 5 | 两位负责人 | 项目工作台 → 迭代协作，创建并开始第1轮迭代，创建下表任务与里程碑 | 任务关联正确迭代、执行人和项目要求 |
| 6 | 普通组员与负责人 | 更新自己的任务为进行中，再填写完成说明并标记已完成 | 进度与已完成任务数量一致；组员不能修改其他成员分工 |
| 7 | 普通组员 | 成果提交 → 准备与提交，上传本队 v1 材料 | 进入待提交材料区，尚无正式回执 |
| 8 | 负责人 | 选中材料、填写成果说明、正式提交 | 生成 v1、受理时间和回执；可下载本版本文件 |
| 9 | 教师 | 团队详情 → 助教检查授权，给 assistant01 授权本项目两队 | 助教可以检查被授权团队 |
| 10 | 助教 | 项目工作台 → 过程检查，选择本队 v1，填写问题并勾选需要整改 | 检查关联具体版本，学生能看到反馈 |
| 11 | 普通组员与负责人 | 组员准备 v2；负责人正式重交，并指定 v2 为最终成果 | v1 仍可下载；v2 有独立回执；最终指定指向 v2 |
| 12 | 助教 | 从原检查进入新版复查，选择 v2，记录整改通过 | 原检查、整改版本及复查结论可以追溯 |
| 13 | 教师 | 等最终截止后，在成果“版本与回执”中核实两队最终成果，确认 v2 为被评版本 | 最终指定与被评引用独立保存，二者都明确显示 v2 |
| 14 | 教师 | 同伴互评 → 创建批次（截止设为次日）→ 分配评审 | 评审对象固定到 v2；两队场景每人只评另一队，不要求凭空分配第二个不同团队 |
| 15 | 四名学生 | 打开自己的待评任务，查看成果、填写维度分和评语、正式提交 | 无自评、无重复有效计分；未完成评审保持可识别状态 |
| 16 | 教师 | 开放互评反馈；进入教师评分，先保存草稿再正式提交 | 草稿不会当作正式评分来源；学生按权限查看反馈 |
| 17 | 教师 | 汇总与发布 → 核对两队计分名单 → 发布当前项目成绩 → 导出课程 XLSX | 当前范围只发布新项目；课程导出包含该课程全部已发布成绩，可按项目筛选 |
| 18 | 四名学生 | 评分与成绩，查看本人成绩、被评版本和依据 | 两队成员分别看到本队对应结果，不能查看其他学生的私人成绩 |
| 19 | 各角色 | 站内通知、过程记录；切换业务入口并返回项目工作台 | 通知带课程/项目/团队名称，页面保持所选项目与团队，记录可追溯 |

如果需要现场快速进入评审，在所有提交与最终指定完成后、原截止到达前，由教师将组队截止调整为当前时间后 2 分钟，将项目截止调整为当前时间后 5 分钟，并等待截止。保留此次关键变更与通知；截止已过时使用授权补交流程，保留真实迟交标记。

### 迭代任务与材料示例

| 团队 | 负责人任务 | 组员任务 | 里程碑 |
|---|---|---|---|
| 拾光队 | 梳理失物登记与查询流程 | 设计认领核验与失败反馈 | 需求方案可评审：两项任务完成，正常与异常场景均有验收条件 |
| 寻迹队 | 设计归还记录与交接流程 | 补充重复归还及隐私验收 | 需求方案可评审：两项任务完成，归还及隐私异常可复现 |

拾光队 v1 说明正常认领流程，v2 增补“认领证据不一致时拒绝确认并提示补充依据”的规则和验收条件。寻迹队 v1 说明正常归还流程，v2 增补“重复归还不重复生成交接结果”和“普通查询不展示联系方式”的规则和验收条件。

助教 v1 反馈分别写“缺少证据不符的处理及验收条件”和“缺少重复归还与隐私验收”；v2 复查写“已补齐对应异常及验收条件，整改通过”。

### 可独立复算的评分示例

| 被评团队 | 教师三个维度 | 教师总分 | 其他队每位评审人的三个维度 | 互评均分 | 最终成绩 |
|---|---|---|---|---|---|
| 拾光队 | 37、32、23 | 92 | 36、30、22 | 88 | 92×70%＋88×30%＝90.80 |
| 寻迹队 | 35、30、21 | 86 | 37、32、21 | 90 | 86×70%＋90×30%＝87.20 |

四名学生各对另一队提交一份评审。若某份互评尚未完成，先演示成绩来源异常提示，再补齐后发布，不能把缺失来源自动记为零分。

## 3. 按身份核对权限与操作

### 普通组员

| 用例 | 操作 | 预期 |
|---|---|---|
| U-M01 申请与加入 | 申请入队，等待负责人审批，重新打开团队详情 | 审批前后权限随有效成员关系变化 |
| U-M02 执行任务 | 更新分配给自己的任务，填写进展说明 | 自己的任务进度保存；任务归属与执行人正确 |
| U-M03 准备成果 | 上传本轮材料并查看材料列表 | 材料显示准备人；上传材料与正式提交区别清楚 |
| U-M04 职责边界 | 查看成果页及其他成员任务操作区 | 不提供负责人正式提交、最终指定及他人分工修改权限 |
| U-M05 评审与成绩 | 提交已分配互评，教师发布后查询本人成绩 | 对象、版本、维度、评语和本人结果一致 |

### 团队负责人

| 用例 | 操作 | 预期 |
|---|---|---|
| U-L01 组队与分工 | 建队、审批组员、安排迭代与任务 | 仅管理本人团队，重复有效归属被阻止 |
| U-L02 交付与重交 | 正式提交 v1，修改材料再提交 v2 | 新增版本、不覆盖、不撤回；回执和历史可下载 |
| U-L03 最终指定 | 截止前指定 v2；再查看版本历史 | 当前有效版本、最终指定、教师被评引用分别显示 |
| U-L04 截止与补交 | 截止后尝试提交；申请补交并获批后再交 | 普通提交关闭；授权内成功，保留真实受理时间和迟交标记，不自动扣分 |
| U-L05 交接 | 选择本队有效组员交接负责人，再用两账号检查 | 新负责人获得管理权限；原负责人保留普通成员权限；历史提交人不被改写 |

### 助教

| 用例 | 操作 | 预期 |
|---|---|---|
| U-A01 检查范围 | 教师授权后打开过程检查 | 可访问授权团队，不能检查未授权团队 |
| U-A02 具体版本检查 | 选择 v1 并给出整改意见 | 检查绑定 v1，后续重交不把原检查自动改绑到 v2 |
| U-A03 整改复查 | 从原检查选整改后 v2 复查 | 原检查、新版本和复查可追溯；旧版不能冒充整改新版 |
| U-A04 评分边界 | 查看工作台及成绩入口 | 正式评分、发布及更正由教师处理，助教不获得相应权限 |

### 教师

| 用例 | 操作 | 预期 |
|---|---|---|
| U-T01 发布与规则 | 填写完整标准后发布；在允许窗口修改关键要求 | 规则与时间一致；关键变更保留记录并通知受影响人员 |
| U-T02 人员管理 | 按姓名/账号选择课程学生，分配到团队 | 通过候选选择完成分配，无需手填内部数字编号 |
| U-T03 评价对象 | 截止后确认具体成果版本，创建互评 | 已提交并可访问的版本成为评价依据 |
| U-T04 正式评分 | 保存部分草稿，重开后补齐并正式提交 | 草稿保留；未填项不能冒充正式零分 |
| U-T05 范围发布 | 在新项目内发布当前范围成绩 | 其他项目不受影响；缺失来源或未核对名单时给出原因 |
| U-T06 成绩更正 | 将拾光队教师第一维度 37 改为 35，再以原因更正已发布成绩 | 教师总分 90，最终成绩 89.40；保留原 90.80 和更正链 |
| U-T07 结束与归档 | 点击结束、终止、归档，查看确认提示后取消 | 取消保持项目原状态；确认后由后端校验并执行合法状态转换 |

## 4. 跨模块和异常验收

| 编号 | 场景 | 必须达到的结果 |
|---|---|---|
| X-01 | 从工作台选择寻迹队，进入迭代，再从侧栏切成果、检查、成绩、过程记录 | 全程保持同一课程、项目、团队；不跳到第一个其他团队 |
| X-02 | 返回项目工作台，再次进入业务 | 仍选中刚才的操作团队 |
| X-03 | 退出教师，登录学生或助教 | 不继承上一账号的工作空间与操作权限 |
| X-04 | 当前项目在本模块没有可访问团队 | 显示空状态，不能回退到另一项目继续操作 |
| X-05 | 切换课程 | 清除原课程项目/团队范围，不错误沿用旧课程筛选 |
| X-06 | 输入超维度满分或缺少评语 | 指出不满足要求的字段，不形成有效正式评分 |
| X-07 | 不完整材料、超单文件 50 MB 或版本总量 200 MB | 拒绝不合格材料或正式提交，保留之前有效版本 |
| X-08 | 普通学生尝试管理其他团队或查看他人私人成绩 | 服务端拒绝，页面不泄露受限内容 |
| X-09 | 截止后普通重交、重新指定最终成果 | 根据窗口与冻结状态阻止；批准补交不把迟交改成按时 |
| X-10 | 未完成必要互评、未正式评分、未核对名单 | 说明缺失来源，不能错误发布成绩 |
| X-11 | 同名团队、重复申请、自评、重复有效评审 | 按项目规则阻止，不生成重复业务结果 |
| X-12 | 点击终止项目后取消 | 不改变项目状态或历史数据 |
| X-13 | 窄屏打开工作台、通知、操作对话框 | 主操作可见、文字可读、按钮可触达，长表格可横向滚动 |
