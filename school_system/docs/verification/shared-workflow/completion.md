# 功能补齐与验收

## 功能验证

| 项目 | 核验结果 |
|---|---|
| 组队申请失效 | 已接入后台失效任务与即时审批限制。重新开放后可重新申请，旧失效事件可在过程记录里查询。集成测试覆盖关闭与重新开放。 |
| 助教授权 | 教师从团队详情授予或撤销团队检查权限。集成测试覆盖非教师不能调整授权、撤销后拒绝团队检查和成果访问、只能看到授权团队的评审人。 |
| 互评状态与计分 | 已接入开始评审、评审中、待复核与逾期标识。复核及重评期间，成绩接口按争议与有效来源检查。实测打开评审、提交维度分及从成绩反查评审。 |
| 失败通知 | 管理页汇总通用及成果通知。实测构造失败、普通教师重试被拒、管理员重试成功、同一接收人保持一条。 |
| 历史分页 | 按时间、类别、事件编号继续读取，每页 50 条。含同时间戳的 322 条记录通过逐页验证。 |
| 课程数据留存 | 管理员登记结束，课程满两年由业务审批人批准，另一管理员账号执行。实测未满两年和争议暂缓均拦截，清理后保存审计，重复执行保持一致。模拟日期只在隔离恢复库回拨，原始样例及附件保留。 |

## 浏览器抽查

管理员打开课程数据留存和投递失败通知。教师从课程项目进入团队详情并打开助教授权对话框。助教工作区显示授权范围的评审记录。学生进入本团队过程记录并查看关联编号筛选。完整业务操作由隔离 HTTP 与集成测试覆盖，逐模块所有异常路径没有全部重复用浏览器点测。

## 性能

环境为本地 Windows、Java 21、H2 文件模式和独立 HTTP 服务。新增 1,000 个合成账号及 10 门课程，目标课程含 200 名学生、50 支团队。50 个独立账号各用一个登录会话并行查询项目详情。10 个团队在附件传完后同时发起正式提交，得到 10 个不同受理版本。汇总读取 50 个团队，导出样本含 1 个已发布团队的成绩。

| 操作 | 实测 | 需求目标 |
|---|---|---|
| 项目详情查询 | 50 路，P95 39.96 ms | P95 ≤ 2 秒 |
| 正式成果受理 | 10 路，P95 48.70 ms | P95 ≤ 3 秒 |
| 成绩汇总 | 5 次，最大 15.02 ms | ≤ 5 秒 |
| 导出 CSV / XLSX | 各 5 次，最大 8.47 / 541.13 ms | ≤ 10 秒 |

## 恢复及清理

数据库及 10 个附件一起打包，校验后恢复至独立目录并启动后端。从恢复开始至业务核对完成用时 15.931 秒。已核对最终版本、被评引用、附件字节、助教检查、互评 80 分、发布成绩 87 分及学生访问。演练快照涵盖全部已知测试写入，抽查记录零回退。此为一次计划内演练，长期故障场景中的数据回退取决于备份频率。

随后在恢复副本实测清理 1 个课程项目的 50 个团队、10 个版本、1 个正式成绩与 10 个附件。课程清理审计仍可查看，原快照保有 10 个附件。

原始耗时与检查结果见同目录 completion-evidence.json。运行留存功能时，在后端启动环境配置 RETENTION_APPROVER 为业务审批人的登录名，清理由另一启用的平台管理员执行。
