# 基础接口约定

所有接口以 `/api` 开头。同源 Cookie 会话认证；课程角色从课程成员关系中查询，不接受前端传入角色作为授权依据。

## 统一响应

```json
{ "code": "OK", "message": "成功", "data": {} }
```

错误使用相应HTTP状态和 `code/message/data`，不返回堆栈、SQL、密码或令牌。下载接口直接返回附件，前端不要按JSON解析。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/health | 服务状态、演示/正式模式、北京时间 |
| GET | /api/auth/csrf | 获取CSRF头名和token，可匿名调用 |
| POST | /api/auth/login | URL编码表单 username、password，须携带CSRF头 |
| GET | /api/auth/me | 当前用户公开字段 |
| POST | /api/auth/logout | 注销会话，须携带CSRF头 |
| GET | /api/courses | 当前账号的有效课程及在各课程的角色 |
| GET | /api/courses/{id} | 课程详情，须有有效课程关系 |
| GET | /api/courses/{id}/management | 课程教师专用的学生人数信息 |
| POST | /api/files | multipart：courseId、file；私有待提交材料，须携带CSRF头 |
| GET | /api/files/{uuid} | 上传者下载本人文件，同时重新校验课程资格 |
| GET | /api/courses/{id}/audit?page=0 | 教师查询操作记录，每页20条 |

## 会话与CSRF顺序

1. GET `/api/auth/csrf`，保留Cookie，取响应中的headerName、token。
2. POST登录，保留Cookie并携带token。Spring Security在登录时更换会话标识。
3. 登录成功后重新获取CSRF token；刷新页面时可重新查询当前用户。
4. POST/PUT/PATCH/DELETE均须携带token；退出后token重新获取。前端不自动重试写操作。
5. 401返回登录页；403提示权限或安全凭证问题。接口授权始终由后端执行。

## 数据及访问边界

- 用户没有全局课程角色；负责人职责将在团队成员关系中实现，不新增全局负责人角色。
- 平台管理员身份不绕过课程权限。团队材料、正式成果与评审授权将在相应模块分别实现。
- 个人待提交文件只允许上传者下载；不会因为教师或管理员身份自动获得访问权。
- UUID文件名存放于非公开目录；下载固定为附件并禁用缓存，文件内容不会在站内执行。
- 上传目前仅做大小、扩展名及完整性校验，内容扫描、正式版本200 MB总量与引用校验属于后续文件/成果完善事项。
- 关键业务服务须在同一事务中调用 `AuditService.append`。文件落盘失败不保存有效元数据；数据库事务失败时回收该次落盘文件。进程突然退出可能残留无元数据文件，后续清理任务应按引用核对后回收。
- 时间显示统一Asia/Shanghai；数据库时间以带时区字段保存。
