# 框架与后续接入

## 项目结构

```text
school_system/
  frontend/src/
    api/        请求、CSRF、接口类型
    stores/     当前用户会话状态
    router/     路由和登录保护
    layouts/    顶部、菜单、内容区域
    views/      登录、课程列表、课程详情、未开放页面
  backend/src/main/java/cn/edu/school/
    auth/       用户、登录、当前用户
    course/     课程关系、角色及权限服务
    common/     统一响应、异常和健康接口
    config/     安全与演示初始化
    file/       个人材料存储与授权下载
    audit/      事务内操作记录
    project/ team/ collaboration/ submission/
    inspection/ review/ grade/ notification/
  backend/src/main/resources/db/migration/
  deploy/       PostgreSQL、后端、Nginx部署
  scripts/      前后端启动及构建
  docs/         约定与交付记录
```

后八个业务包目前只有边界说明。课程列表来自数据库；未开放模块不调用假接口。

## 接入顺序

1. 项目：发布校验、要求版本、组队及最终期限、评分配置、生命周期。
2. 团队：申请审批、唯一归属、人数并发校验、负责人交接、教师调整及历史。
3. 协作：团队自主迭代、任务归属、里程碑、手动结束与遗留任务调整。
4. 成果：负责人正式提交、不可覆盖版本、幂等回执、最终指定、截止冻结及限时补交。
5. 评审检查：标准版本、分配、匿名、有效评审与重评、检查反馈与复查。
6. 成绩：名单快照、有效来源、精确计算、发布及更正版本、CSV/XLSX导出。
7. 通知：事务事件、接收范围、去重、三次重试和时间提醒。

每项功能一起完成迁移脚本、实体服务、接口、页面和权限验证。新迁移从V2开始；已应用的迁移不改写。数据库目前只为框架建表，不提前固定尚未实现模块的全部字段。

## 必须保留的业务规则

- 教师项目要求与团队内部任务分开；只有一层迭代，任务属于迭代。
- 普通成员准备材料，负责人正式提交；上传不能生成正式提交回执。
- 当前迭代版本、最终指定版本、评审引用版本分别保存。
- 重交新增版本、不撤回、不自动替换最终或评审引用。
- 任务计划时间不自动生成延期；最终交付以成功受理时间判断。
- 课程授权、对象归属、状态、时间窗口均在后端判断。
- 互评与成绩保留版本；必要来源异常阻止发布，已发布更正采用新版本。

## 框架边界

当前可验证登录与课程隔离、私有文件访问和操作记录。项目级状态、团队级权限、业务幂等、通知、性能负载和RPO/RTO仍随业务模块实施，不能把框架启动成功登记为完整系统验收通过。
